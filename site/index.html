Your local dev stack, in one window.

DevsPro runs nginx or Apache sites with trusted HTTPS, Docker, databases, queue workers, mail, logs and ports from one desktop app for Linux and Windows. Anything that needs root or administrator rights goes through one small helper that can only do a fixed list of things.

  • Scheduled tasks

    Recurring commands on a schedule, with each run's output and, for a failed run, the matching Laravel log entry.

  • Redis

    Browse keys by pattern and watch Laravel queues: pending, delayed and reserved.

How privilege works

Root only where it's needed. Never for arbitrary commands.

DevsPro itself never runs elevated. Anything that needs root or administrator rights (web server config, the hosts file, the certificate trust store, package installs) goes through one small helper binary that applies a declared manifest of operations and exits. On Linux it is started with pkexec; on Windows, through a UAC prompt.

  • Write a file under one allowed prefix
  • Sync a marker-delimited block
  • Install named packages
  • Test and reload nginx or Apache
  • Trust the local root CA
  • Start or stop a system service
  • Install a verified DevsPro update
  • There is no run this command

On Windows the installer puts DevsPro and its helper in Program Files, where only administrators can write, so no other program can swap the helper before DevsPro elevates it. On Linux, what doesn't need root doesn't get it: nvm installs into ~/.nvm, npm globals go to your own npm prefix, and binaries like cloudflared land in ~/.local/bin.

What the helper receives when you add a site on Linux
{
  "allowed_write_prefix": "/home/you/.local/share/com.soab.devspro",
  "operations": [

      "conf_d_dir": "/etc/nginx/conf.d",
      "sites_glob":
        "/home/you/.local/share/com.soab.devspro/nginx/sites/*.conf" },
    { "type": "SyncMarkedBlock",
      "file_path": "/etc/hosts",
      "marker_begin": "# >>> devspro (do not edit this block manually) >>>",
      "marker_end": "# <<< devspro <<<",
      "block_lines": ["127.0.0.1 shop.test"] },
    { "type": "RunNginxTest", "binary_path": "/usr/sbin/nginx" },

Updates

Updates itself, and checks the signature twice.

DevsPro looks for a new version when it starts, every six hours after that, and whenever you ask in Settings → Updates. When one is out, the top bar says so. An update installs only if it was signed with the DevsPro release key, and never one older than what you have.

  1. Check

    Reads the release feed and compares versions. You see the release notes before anything downloads.

  2. Download and verify

    Fetches the package that matches how you installed it (.deb, .rpm or the Windows installer) and checks its minisign signature.

  3. Verify again, elevated

    The helper checks the signature itself against a key compiled into it, and refuses downgrades. On Linux, apt or rpm installs it after one password prompt; on Windows, the installer runs in passive mode, a progress bar only, after one UAC prompt.

  4. Restart

    DevsPro restarts on the new version, as you rather than elevated, with your sites, services and settings where you left them.

Install DevsPro

For 64-bit Linux and Windows. Install once by hand; after that DevsPro updates itself.

Linux

Debian, Ubuntu, Pop!_OS

The .deb package.

sudo apt install ./DevsPro_*_amd64.deb
Download .deb

Fedora, RHEL

The .rpm package.

sudo dnf install ./DevsPro-*.x86_64.rpm
Download .rpm

Needs pkexec (polkit), which both packages depend on. The package also installs the polkit policy that lets the helper ask for your password.

Windows

Windows, 64-bit

One installer: DevsPro_*_x64-setup.exe

  1. Run it and approve the administrator prompt. It installs for every user on the machine, into Program Files, so Windows asks with UAC.
  2. If SmartScreen says “Windows protected your PC”, choose More info, then Run anyway. The installer isn't code-signed yet, so you'll see this the first time.
  3. No WebView2? It's fetched for you. If Microsoft Edge WebView2 is missing, the installer downloads it.
Download for Windows

Why it installs for all users

DevsPro starts its helper with administrator rights. In Program Files only administrators can change that file, so a program running as you can't replace the helper and wait for DevsPro to elevate it. A per-user install would leave it writable.

Updates after this one install from inside DevsPro, checked against its own signing key first.

FAQ

Questions

Which systems does it run on?

64-bit Linux and Windows. On Linux, the .deb is for Debian, Ubuntu, Pop!_OS and their relatives, and the .rpm is for Fedora and RHEL. On Windows there is one installer, DevsPro_<version>_x64-setup.exe. There is no macOS version.

Does it run on Windows?

Yes, every module does. A few things work differently because Windows does: elevation is a UAC prompt, Laravel sites run on php-cgi.exe that DevsPro starts on a port per PHP version, Firefox needs security.enterprise_roots.enabled to trust the local CA, and stopping a worker ends it rather than letting it finish its job. The full list is under Linux and Windows.

Why does Windows warn about the installer?

The installer isn't code-signed yet; that needs a code-signing certificate. Until it is, SmartScreen shows “Windows protected your PC” the first time you run it: choose More info, then Run anyway.

Updates after that don't depend on Windows' signing: DevsPro checks each one against its own minisign key, and its elevated helper checks again before it runs the installer.

Why no AppImage or Flatpak on Linux?

Elevation needs a polkit policy file in /usr/share/polkit-1/actions/, and only an installed package can put it there. Without it, every action that needs root (nginx config, /etc/hosts, the trust store, package installs) would fail, and that is most of the app.

What can DevsPro do with root or administrator rights?

Only the operations the helper knows: write files under one allowed prefix, sync a marked block in a file like /etc/hosts, install named packages, test and reload nginx or Apache, trust the local CA, fix a Laravel project's storage permissions, start or stop a system service, a few memory and disk cleanup tasks (the apt cache, journal and old snaps on Linux; Windows Temp, the Update and Delivery Optimization caches and crash dumps on Windows), and install a signed DevsPro update. Each run asks first: for your password through pkexec on Linux, with a UAC prompt on Windows. There is no operation that runs an arbitrary command.

Does it send anything anywhere?

No telemetry and no online account. Apart from the update check, DevsPro only goes online when you ask it to, for example to install a tool, open a tunnel or load a page in its browser. Your sites, services and settings stay on your machine (in ~/.local/share/com.soab.devspro on Linux), and Settings → Backup & restore exports them to one file.

How do updates work?

DevsPro reads a small release feed, downloads the package that matches how you installed it, and checks its minisign signature. The elevated helper checks the signature again before it installs, so even a tampered download that got past the app would be refused, and it refuses anything older than the version you have.

On Linux you confirm with your password and apt or rpm installs the package. On Windows you approve one UAC prompt and the installer runs in passive mode, showing only a progress bar. Then DevsPro restarts on the new version, as you.

What does it cost?

Nothing. DevsPro is free and released under the MIT license.

Do I need Docker?

Only for the modules built on it: Docker, Databases and the Data browser, plus the Cleaner's Docker tab. The Mail Catcher runs Mailpit without Docker, and sites, workers, scheduled tasks, Redis, the terminal, Files and the rest work without it too.

If Docker isn't installed, those pages offer to install it from the Apps module (on Windows you can pick the Docker Desktop version). If it's installed but not running, a Start Docker button starts it and waits until it's ready.
